# Telegram-бот «Обратная связь»

Полноценный бот для двусторонней переписки между пользователями и владельцем.
Пользователь пишет боту — владелец получает аккуратную карточку и может ответить
прямо из Telegram. Ответ приходит пользователю **от имени бота**, без раскрытия
личных данных владельца.

Проект написан на **Python 3.12 + aiogram 3**, работает через **long polling**,
хранит данные в **SQLite** и не требует Flask, Django, FastAPI, Docker или
внешней базы данных.

---

## Возможности

### Для пользователя

- Отправка текста, фотографий, видео, видеосообщений (кружков), голосовых,
  аудио, GIF, документов, стикеров и альбомов.
- Подпись к медиа сохраняется и передаётся владельцу.
- Ответ владельца приходит в тот же чат от имени бота.
- Понятные сообщения об ошибке, ограничении отправки и блокировке.
- Команды `/start`, `/help`, `/cancel`.
- Пользователь не видит других пользователей и не получает личные данные
  владельца.

### Для владельца

- Панель управления на русском языке с реальной статистикой из SQLite.
- Разделы: новые сообщения, все диалоги, пользователи, чёрный список, настройки.
- Карточка каждого сообщения: ID пользователя, имя, username, номер диалога,
  время, тип вложения и текст/подпись.
- Ответ через кнопку «Ответить» или обычный Telegram Reply на карточку.
- Профиль пользователя, история диалога, блокировка/разблокировка,
  закрытие/открытие диалога, обновление карточки, возврат в меню.
- Команды `/menu`, `/cancel`, `/ban`, `/unban`, `/help`.
- Уведомления о недоставленных ответах и служебные подсказки.

### Технические особенности

- Стабильные внутренние номера диалогов, сохраняются в SQLite.
- Привязка сообщений владельца к диалогам переживает перезапуск бота.
- Нет глобальной переменной `current_user_id` — маршрутизация идёт по Reply
  или по явному состоянию выбранного диалога.
- Альбомы собираются с ограниченной задержкой, максимум 10 файлов.
- Ограничение частоты сообщений и защита от «флуда» уведомлениями.
- Повторные вызовы Telegram API при `FloodWait`, `RetryAfter` и сетевых сбоях.
- Дедупликация `update_id` через SQLite.
- WAL-режим SQLite, параметризованные SQL-запросы, автоматическая инициализация.
- Медиафайлы **не скачиваются и не хранятся**; в базе только короткие текстовые
  превью для истории.
- Группы, каналы и сообщения не из личных чатов игнорируются.
- Владелец никогда не попадает в пользовательский сценарий.

## Быстрый старт

### 1. Создайте бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте имя и username бота.
3. Скопируйте токен вида `123456789:AA...`.
4. Дополнительные настройки BotFather не обязательны: бот работает только
   в личных чатах. Добавлять его в группы не нужно.
5. При желании задайте описание и аватар бота через `/setdescription`
   и `/setuserpic`.

Токен — секрет. Не публикуйте его, не коммитьте в Git и не отправляйте
скриншоты с ним.

### 2. Узнайте свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) или
[@getmyid_bot](https://t.me/getmyid_bot). Бот покажет числовой ID, например
`123456789`. Это значение нужно для `OWNER_ID`.

`OWNER_ID` — только число. Username (`@nickname`) не подойдёт.

### 3. Установите Python 3.12

Скачайте Python 3.12 с [python.org](https://www.python.org/downloads/) и при
установке включите **Add python.exe to PATH**.

Проверка:

```bash
python --version
```

Ожидается `Python 3.12.x`.

### 4. Создайте виртуальное окружение

**Windows (PowerShell):**

```powershell
cd C:\path\to\tg
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если PowerShell блокирует активацию:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Linux / macOS:**

```bash
cd ~/path/to/tg
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 5. Создайте `.env`

Скопируйте пример:

**Windows:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

Откройте `.env` и укажите реальные значения:

```dotenv
BOT_TOKEN=123456789:AAExampleExampleExampleExampleExample
OWNER_ID=123456789
DATABASE_PATH=data/bot.db
LOG_LEVEL=INFO
TIMEZONE=Europe/Moscow
```

Важно: слева от `=` всегда стоят имена переменных `BOT_TOKEN` и `OWNER_ID`.
Справа — токен и числовой Telegram ID. Нельзя писать
`@username_бота=ТОКЕН` или `123456789=МОЙ_ID`: бот не сможет прочитать такую
конфигурацию.

Минимально нужны только `BOT_TOKEN` и `OWNER_ID`. Остальные параметры имеют
безопасные значения по умолчанию.

### 6. Запустите бота

```bash
python main.py
```

В логе появятся строки о запуске long polling и подключении SQLite. Откройте
бота в Telegram, отправьте `/start` — пользовательский сценарий. Затем отправьте
`/menu` из аккаунта владельца — откроется панель.

Остановка: `Ctrl+C`.

> Важно: одновременно должен работать только один экземпляр бота с одним
> токеном. Иначе Telegram вернёт конфликт long polling.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---:|---|---|
| `BOT_TOKEN` | да | — | Токен от BotFather |
| `OWNER_ID` | да | — | Числовой Telegram ID владельца |
| `DATABASE_PATH` | нет | `data/bot.db` | Путь к файлу SQLite |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `TIMEZONE` | нет | `Europe/Moscow` | Часовой пояс для дат в интерфейсе |
| `RATE_LIMIT_WINDOW_SECONDS` | нет | `60` | Окно антиспама |
| `RATE_LIMIT_MAX_MESSAGES` | нет | `30` | Максимум сообщений за окно |
| `RATE_LIMIT_MIN_INTERVAL_SECONDS` | нет | `1.0` | Минимальный интервал между сообщениями |
| `RATE_LIMIT_MAX_TRACKED_USERS` | нет | `10000` | Лимит пользователей в памяти антиспама |
| `RATE_LIMIT_WARNING_COOLDOWN_SECONDS` | нет | `30` | Пауза между предупреждениями |
| `MEDIA_GROUP_DELAY_SECONDS` | нет | `0.8` | Ожидание досбора альбома |
| `MEDIA_GROUP_MAX_BUFFERS` | нет | `500` | Максимум одновременных альбомов в буфере |
| `MEDIA_GROUP_MAX_ITEMS` | нет | `10` | Максимум файлов в альбоме |
| `HISTORY_RETENTION_DAYS` | нет | `30` | Срок хранения текстовой истории |
| `HISTORY_PAGE_SIZE` | нет | `15` | Сообщений в истории диалога |
| `ADMIN_PAGE_SIZE` | нет | `8` | Элементов на странице списков |
| `TELEGRAM_MAX_RETRIES` | нет | `2` | Повторы при сбоях Telegram |
| `FLOODWAIT_MAX_SECONDS` | нет | `60` | Максимальная пауза FloodWait |
| `MAINTENANCE_INTERVAL_SECONDS` | нет | `21600` | Интервал очистки базы (6 часов) |

Все значения валидируются при старте. При ошибке бот завершится с понятным
сообщением, не раскрывая токен.

## Команды

### Пользователь

| Команда | Действие |
|---|---|
| `/start` | Приветствие и начало работы |
| `/help` | Как работает бот |
| `/cancel` | Сообщает, что активных действий нет |

### Владелец

| Команда | Действие |
|---|---|
| `/menu` или `/start` | Панель управления |
| `/cancel` | Отменить режим ответа |
| `/ban #12` | Заблокировать диалог по номеру |
| `/ban 123456789` | Заблокировать по Telegram ID |
| `/unban #12` | Разблокировать |
| `/help` | Список команд владельца |

`/ban` и `/unban` также работают как ответ на карточку сообщения.

## Как отвечать пользователю

Есть два способа.

1. **Кнопка «Ответить»** под карточкой. Бот покажет подсказку и запомнит
   выбранный диалог. Следующее отправленное сообщение или альбом уйдёт
   пользователю. Отмена — `/cancel` или кнопка «Отменить».
2. **Обычный Telegram Reply** на карточку сообщения или на скопированное
   вложение. Этот способ работает даже после перезапуска бота, потому что
   привязка хранится в SQLite.

Ответ всегда отправляется через `copyMessage` / `copyMessages`. Бот не
использует `forwardMessage`, поэтому пользователь не увидит личный аккаунт
владельца и не сможет перейти в его профиль.

## Запуск тестов

Установите dev-зависимости:

```bash
pip install -r requirements-dev.txt
```

Запустите:

```bash
pytest -q
```

Тесты используют мок-объекты Telegram API, временную SQLite и не требуют
реального токена или интернета. Проверяются:

- создание пользователей и диалогов;
- сохранение истории и статистики;
- привязка Reply после перезапуска;
- независимая маршрутизация двух пользователей;
- альбомы и длинный текст;
- антиспам и буфер альбомов;
- ограничение длины HTML-карточки;
- доступ только владельца к callback-кнопкам;
- отсутствие `forwardMessage`.

Дополнительно можно проверить стиль и импорты:

```bash
python -m compileall -q main.py config.py database.py ui.py keyboards.py callbacks.py states.py handlers services
ruff check . --exclude .venv
ruff format --check . --exclude .venv
```

`ruff` не входит в обязательные зависимости; при необходимости установите:

```bash
pip install "ruff>=0.6,<1"
```

Репозиторий должен быть **публичным**, если вы планируете бесплатное
развёртывание на bot-hosting.net через GitHub Source.

```bash
cd C:\path\to\tg
git init
git add .
git commit -m "Telegram feedback bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Перед первым коммитом убедитесь:

```bash
git status
```

В списке не должно быть `.env`, `.venv`, `data/`, `*.db`, логов и токенов.
`.gitignore` уже настроен.

Если токен случайно попал в репозиторий:

1. Немедленно отзовите токен в BotFather (`/revoke`).
2. Создайте новый токен.
3. Удалите файл из истории Git или создайте чистый репозиторий.
4. Обновите `.env` и переменные на хостинге.

## Развёртывание на bot-hosting.net

Ниже — общий порядок для панели bot-hosting.net. Названия пунктов могут
незначительно отличаться в зависимости от версии панели.

### 1. Подготовьте репозиторий

- Код загружен на GitHub.
- В корне лежат `main.py` и `requirements.txt`.
- `.env` в репозиторий **не добавлен**.
- Папка `data/` не нужна: она создастся автоматически.

### 2. Создайте приложение

1. Войдите в панель bot-hosting.net.
2. Откройте раздел **Application Deployment** (или **Deploy Application**).
3. Выберите источник **GitHub Source** / **GitHub Repository**.
4. Подключите GitHub-аккаунт, если панель попросит.
5. Выберите нужный репозиторий и ветку `main`.

### 3. Укажите параметры запуска

- **Runtime / Language:** `Python`
- **Python version:** `3.12` (если доступно; иначе ближайшая 3.12.x)
- **Entry File / Start File:** `main.py`
- **Install command:** обычно панель сама выполняет
  `pip install -r requirements.txt`; если есть отдельное поле, укажите эту
  команду.
- **Start command:** `python main.py` (если панель требует явный `python3`,
  используйте `python3 main.py`).

Если панель требует `Procfile`, создайте его в корне репозитория:

```text
worker: python main.py
```

Для long polling не нужен HTTP-порт и webhook.

### 4. Добавьте переменные окружения

В разделе **Environment Variables** / **Secrets** добавьте:

| Ключ | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `OWNER_ID` | ваш числовой Telegram ID |
| `DATABASE_PATH` | `data/bot.db` |
| `TIMEZONE` | `Europe/Moscow` |
| `LOG_LEVEL` | `INFO` |

Секреты добавляйте только через панель хостинга. Не создавайте `.env`
в публичном репозитории.

### 5. Запустите и проверьте

1. Нажмите **Deploy** / **Start**.
2. Откройте логи приложения.
3. Дождитесь строки о запуске long polling.
4. Напишите боту `/start` с обычного аккаунта.
5. Отправьте `/menu` с аккаунта владельца.
6. Проверьте текст, фото и ответ через кнопку.

### 6. Обновление кода

1. Внесите изменения локально.
2. Сделайте коммит и push в GitHub.
3. В панели нажмите **Redeploy** / **Restart** / **Pull latest**.
4. Проверьте логи после обновления.

База `data/bot.db` должна находиться на постоянном диске. Если хостинг
пересоздаёт файловую систему при каждом деплое, история и привязки Reply
будут потеряны. Уточните в документации хостинга, сохраняется ли рабочая
директория.

## Приватность и безопасность

- Токен и `OWNER_ID` читаются только из окружения.
- Владелец определяется исключительно по `OWNER_ID` из `.env`.
- Каждый обработчик владельца повторно проверяет `from_user.id`.
- Владелец не может случайно попасть в пользовательский сценарий.
- Пользователь не видит ID, username, телефон и профиль владельца.
- Ответы копируются, а не пересылаются: нет ссылки на исходный аккаунт.
- Контакты, геолокация, опросы и dice не пересылаются.
- Медиафайлы не сохраняются на диск и в базу.
- В истории хранятся только короткие текстовые превью.
- SQL-запросы параметризованы.
- В логах нет токена и содержимого сообщений.
- Группы и каналы игнорируются.

Рекомендации:

- Используйте отдельного бота только для этой задачи.
- Ограничьте доступ к панели хостинга и GitHub.
- Периодически отзывайте старые токены.
- Делайте резервные копии `data/bot.db`, если история важна.
- Не добавляйте бота в группы: он рассчитан на личные чаты.

## Ограничения

- Telegram Bot API не позволяет менять цвета и размеры inline-кнопок.
  Интерфейс использует стандартные кнопки и HTML-разметку.
- Бот не может писать пользователю, если тот заблокировал бота.
- История хранится ограниченное время (`HISTORY_RETENTION_DAYS`).
- Медиа в истории не сохраняются — только текстовые превью.
- SQLite рассчитан на один процесс. Не запускайте несколько экземпляров
  с одной базой.
- Long polling несовместим с webhook на том же токене.
- Стикеры и часть типов медиа копируются средствами Telegram; бот не
  скачивает файлы.

## Возможные проблемы

### `BOT_TOKEN не задан` или `OWNER_ID не задан`

Проверьте `.env` в рабочей директории или переменные окружения хостинга.
Убедитесь, что файл называется именно `.env`, а не `.env.txt`.

### `BOT_TOKEN имеет неверный формат`

Скопируйте токен целиком, без пробелов и кавычек. Формат:
`123456789:AA...`.

### `OWNER_ID должен быть числом`

Укажите числовой ID, а не `@username`.

### `TelegramConflictError` / конфликт polling

- Остановите второй экземпляр бота.
- Убедитесь, что у бота не установлен webhook.
- Не запускайте локально и на хостинге одновременно.
- Перезапустите приложение через панель.

### Бот не отвечает

- Проверьте логи.
- Убедитесь, что процесс не завершился.
- Проверьте, что токен действителен.
- Напишите боту `/start` в личный чат.

### Владелец не получает карточки

- Проверьте `OWNER_ID`.
- Нажмите `/start` у бота с аккаунта владельца.
- Убедитесь, что владелец не заблокировал бота.
- Посмотрите логи на ошибки `TelegramForbiddenError`.

### Ответ не доходит пользователю

Пользователь мог заблокировать бота или удалить чат. Бот пришлёт владельцу
уведомление о недоставке. Это ограничение Telegram, а не ошибка кода.

### `database is locked`

- Не запускайте несколько экземпляров.
- Убедитесь, что база на локальном диске, а не на сетевой папке.
- WAL и `busy_timeout` уже включены.

### После перезапуска не работает Reply на старую карточку

Проверьте, что `data/bot.db` сохраняется между перезапусками и не удаляется
при деплое. Привязки хранятся в таблице `owner_messages`.

### Слишком строгий антиспам

Увеличьте `RATE_LIMIT_MAX_MESSAGES` или уменьшите
`RATE_LIMIT_MIN_INTERVAL_SECONDS` в `.env` и перезапустите бота.

## Резервное копирование

Остановите бота или используйте SQLite backup, затем скопируйте:

```text
data/bot.db
data/bot.db-wal
data/bot.db-shm
```

Для обычного восстановления достаточно корректно остановленного `bot.db`.
Не копируйте файл во время активной записи без необходимости.

Код можно использовать и изменять свободно. При публикации рекомендуется
